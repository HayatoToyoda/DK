# 説明の視覚化（高品質を維持する）

## 目的

読者が**文だけでは関係・順序・境界を追いにくい**とき、Mermaid をはじめとする手段で**構造を見せる**。視覚化は付け足しではなく、理解の本体の一部として扱う。

## いつ必ず使うか（トリガー）

次のいずれかに当てはまるなら、**先に図の案を立ててから**文章を整える（または文章と並行する）。

- **対比・分類**が中心（A と B の違い、レイヤ比較、VM とコンテナなど）
- **手順・分岐**がある（セットアップ、トラブルシュート、デプロイパイプライン）
- **時間順・状態**が重要（ライフサイクル、認証フロー、ジョブの状態機械）
- **複数役割の相互作用**（クライアント・サーバ・キュー・DB）
- **階層・包含関係**（スタック、名前空間、モジュール依存の概略）
- 段落が**長く、見出しが少ない**、または**専門用語が連続**している

ユーザーが明示的に「図」を求めていなくても、上記なら**黙って表や図だけ足すのではなく**、一文で「下図は … を表す」と役割を言い、**図＋短いキャプション**で補う。

## ワークフロー

1. **一文で読者のゴールを決める**（その図で読者ができるようになること）。
2. 説明を **共有部分 / 分かれ目 / 各方式の詳細 / 最後に共通して到達する先** に分解する。
3. **情報の種類**から図の型を選ぶ（次節）。
4. **Mermaid で実装**。サブグラフやノードが多いほど、**見出し短め・ID 一意・重なり対策**を先に設計する。
5. 図の直前または直後に、**読み方と共通/差分の要点**を 2〜5 行で添える。
6. **プレビューで可読性を確認**し、可能なら Mermaid を実レンダリングして崩れがないか確かめる。

比較図では、単に「安全に分割できるか」よりも、**読者が同じ高さ・同じ位置で差を見比べられるか**を優先する。分割すると対応関係が消えるなら、1 枚の比較図を保ったまま単純化する。

## 出力の基本形

視覚化を入れるときは、なるべく次の並びを守る。

1. **役割の一文**  
   例: 「下図は、VM とコンテナの共通点と分かれ目を上から下に示します。」
2. **図本体**  
   Mermaid、または表・番号付き手順・ASCII スケッチ。
3. **読み方の補足**  
   最低でも次の 3 点を短く書く。
   - 何が**共通**か
   - どこから**差が出る**か
   - どう読むか（左から右 / 上から下 / 矢印の意味）

## 比較図で「共通」と「差分」を見せる

比較図では、違いだけを並べるより **共有部分を明示してから分岐**させた方が理解しやすい。特に「A と B を比べて説明して」「共通点も差分も整理して」と言われたら、次を優先する。

1. **共通の入口**を 1 つ置く。  
   例: 「狙いは同じ」「両方ともこの問題を解く」。
2. **分かれ目**を名前付きで置く。  
   例: 「ここから先が違う」「分岐点: カーネルを増やすか共有するか」。
3. **差分は中央だけ**に閉じ込める。  
   共有できる要素まで枝ごとに複製しない。
4. **共通の出口**があるなら最後に再合流させる。  
   例: 「どちらも最終的にハードウェアで実行される」。
5. 共有ノードから枝へ伸ばすときは、**関係する要素すべて**に接続する。  
   1 本だけ接続すると、「A だけが対象」のような誤読が起こりやすい。

比較図の定番パターン:

- **上共通 / 中央分岐 / 下共通**  
  共通の目的と共通の到達先がある比較向け。
- **左右比較 + 共通項目を本文で補足**  
  共通項目が少なく、差分の中身を見せたいとき向け。
- **横並びのレイヤ比較**  
  同じ層のどこまでが共通で、どこから違うかを一目で見せたいとき向け。対応する層は**同じ高さ**に置き、列の役割を固定する。
- **図を 2 枚に分ける**  
  共通構造まで 1 枚に入れると大きくなりすぎるとき向け。ただし、**同じレイヤーの対比が主目的なら分けすぎない**。

## 横並びのレイヤ比較

レイヤ構造の比較では、読者は「どの段までは同じで、どの段から変わるのか」を見たいことが多い。このときは、フローの前後関係よりも **対応関係の見やすさ** を優先する。

基本ルール:

1. **列の意味を固定**する。  
   例: 左列 = VM、右列 = コンテナ。
2. **行の意味を固定**する。  
   例: アプリ層 / 分離の仕組み / カーネル / ハードウェア。
3. **同じレイヤーは同じ高さ**に置く。  
   これがないと、読者は「どれとどれを比べればよいか」で迷う。
4. **共通の層は中央に 1 つ置く**か、左右両列に同じ見出しで並べる。  
   「共通」と本文で言うだけで、図に現れない状態で終わらせない。
5. **差が出る段だけ注釈する**。  
   全段に長文を入れるより、分岐点だけ強調した方が読みやすい。

おすすめの構成:

- まず **比較表** で行と列の意味を読者に渡す
- その下に **横並びレイヤ図** を置く
- 必要なら最後に **差分だけ拡大した図 2** を足す

避けること:

- 安全のために図を 2 枚以上に分けた結果、**同じレイヤーの対応が目で追えなくなる**こと
- 左右比較のはずなのに、片方だけ詳細で片方が抽象的になること
- 「共通」と言いながら、図では左右が完全に独立して見えること

## Mermaid の型の選び方

| 読者が知りたいこと | 推奨 | メモ |
|---|---|---|
| 処理の順序・分岐 | `flowchart` | 比較は `LR` や図の分割で重なりを避ける |
| 誰が誰とメッセージするか | `sequenceDiagram` | 同期API・認証・非同期は注釈で補足 |
| 状態と遷移 | `stateDiagram-v2` | 複雑なら状態を減らすか複数図に分ける |
| クラス/モジュール関係（概略） | `classDiagram` | 細部より「依存の向き」が伝われば十分なことが多い |
| 時系列の並び | `gantt` または本文のタイムライン表 | 用途に合わせる |

レンダラが古い・制限がある場合は、**図を二段に分ける**か、**表＋番号付き手順**に落とす。

## 高品質に保つ（Mermaid 実務ルール）

**重なり・崩れ（特に Cursor / VS Code / GitHub プレビュー）**

- **並列の `subgraph` を `flowchart TB` で並べない**のが基本。比較図は **`flowchart LR`**、または **`mermaid` ブロックを 2 つ**に分ける。
- **サブグラフの見出しは短く**し、長い説明は**本文またはキャプション**へ。
- 長いノードラベルは `["1行目<br/>2行目"]` で折り返す。
- **ノード ID は図全体で一意**（複数サブグラフで `A1` の使い回し禁止）。
- 必要なら先頭に（効かない環境もあるが害は小さい）:

  `%%{init: {'flowchart': {'nodeSpacing': 32, 'rankSpacing': 48, 'padding': 16, 'subgraphTitleMargin': 8}}}%%`

**意味の品質**

- **矢印の向き**を統一（例：データは左→右、依存は上→下など、一図一ルール）。
- **ノード数を絞る**。「全部載せ」より、**読者の質問1つに答える1枚**を優先。別視点は別図。
- **略語**は初出で展開するか、図直下にミニ用語集を付ける。
- 比較図では、**同じレイヤーのノード幅・粒度を揃える**。片側だけ 3 段、片側だけ 5 段だと対応関係が崩れる。

**確認**

- 保存後、**Markdown プレビューで図を開き**、重なり・はみ出しを確認してから完了とする。
- 可能なら Mermaid を **実レンダリング**して、構文ミスや環境差による崩れを早めに見つける。

  例:

  `npx -y @mermaid-js/mermaid-cli@latest -i /tmp/input.mmd -o /tmp/output.png`

  実レンダリングに失敗したら、図を複数に分ける、サブグラフ見出しを短くする、ラベルを改行する、の順で単純化する。

## Mermaid 以外の視覚化

次も「図に近い役割」として積極的に使う。

- **表**（2〜4 列の比較、用語と一言定義）
- **番号付き手順**＋各ステップ 1 行要約
- **インデント付き箇条書き**で階層（親子だけを示すとき）
- **短い ASCII スケッチ**（レイアウトが単純で Mermaid が重いとき）

## アンチパターン

- 図が**正確性を落とす**なら載せない（不確かな部分は点線・注釈・「概略」と明記）。
- **同じ内容を**長文と図で**完全二重執筆**しない。一方を主、一方を要約にする。
- 「とりあえず巨大な1枚」より、**小さな図を複数**。
- 対応関係が主題なのに、**安全のためだけに図を分割して比較軸を壊す**。
- 分岐図なのに**分かれ目の名前がない**、あるいは共通項目が本文にしかなく図に現れない状態で終わらせない。
- 比較図で、共有の起点があるのに **片方の枝の一部にしか矢印を引かない** ことで誤読を招かない。
