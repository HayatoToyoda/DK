# 答え合わせ 01

## 課題 1: Alpine Linux を起動してみる

```bash
# alpine コンテナを起動してシェルに入る
docker run -it alpine sh

# コンテナの中で実行
cat /etc/os-release
# NAME="Alpine Linux"
# VERSION_ID=3.x.x
# ...

exit
```

`alpine` イメージはわずか数 MB の超軽量 Linux です。
Ubuntu（約80MB）と比べてもかなり小さく、ベースイメージとしてよく使われます。

## 課題 2: コンテナのライフサイクルを確認する

```bash
# 1. 起動
docker run -d -p 8081:80 --name my-web nginx

# 2. 確認
docker ps

# 3. ログ確認
docker logs my-web

# 4. 停止
docker stop my-web

# 5. 停止状態の確認（STATUS が Exited になっている）
docker ps -a

# 6. 削除
docker rm my-web

# 7. 消えたことを確認
docker ps -a
```

## 課題 3: 考えてみよう

**1. イメージとコンテナの違い**

イメージ = 「設計図」「金型」「クッキーの型」
コンテナ = 「設計図から作った実体」「型から作ったクッキー」

1つの型（イメージ）から、同じ形のクッキー（コンテナ）をいくつでも作れます。

**2. 環境差異が解決できる理由**

コンテナはアプリの実行に必要なもの（コード・ライブラリ・ランタイムのバージョン）をすべて内包しています。
ホストのPCやサーバーの環境に依存しないため、「どこで動かしても同じ環境」が保証されます。

**3. `-p 8081:80` の意味**

```
-p ホスト側ポート:コンテナ側ポート
       8081    :    80
```

- 左（8081）: あなたのMacのポート番号。ブラウザで `localhost:8081` にアクセスするときのポート
- 右（80）: コンテナの中で nginx が待ち受けているポート番号

「Mac の 8081 番に来たアクセスを、コンテナの 80 番に転送する」という意味です。
